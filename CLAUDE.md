# Затея — конвенции для агентов

Платформа запуска геймифицированных промо-механик и мотивационных программ.
Механики: викторина, колесо фортуны, «собери набор», промокоды. Каналы участия:
веб, Telegram-бот, VK mini app. Живой рейтинг, атомарная выдача призов и промокодов,
доменные события в очередь.

## Технический стек

- PHP 8.5, Laravel 12, Laravel Octane на RoadRunner.
- PostgreSQL (хранилище), Redis (рейтинг, счётчики попыток, ограничение частоты),
  RabbitMQ (доменные события, отложенная выдача призов и уведомления).
- Centrifugo — веб-сокеты для живого рейтинга и всплывающих уведомлений о выигрыше.
- Спецификация внешнего программного интерфейса — OpenAPI 3.1 (`docs/openapi/openapi.yaml`).
- Docker и docker compose — единый способ поднять всё окружение.

## Архитектура — чистая архитектура (Роберт Мартин)

Зависимости направлены строго внутрь: `Presentation → Application → Domain`,
`Infrastructure → Application → Domain`. Внутренний слой ничего не знает о внешнем.

- `src/Domain/` — сущности предметной области, объекты-значения, доменные события,
  интерфейсы хранилищ. Чистый PHP, запрещены `Illuminate\*`, обращения к базе, к сети.
- `src/Application/` — сценарии использования (команда + обработчик + результат),
  порты инфраструктуры (интерфейсы). Зависит только от `Domain`.
- `src/Infrastructure/` — реализации портов и хранилищ: Eloquent, клиент Centrifugo,
  публикатор RabbitMQ, хранилище рейтинга в Redis. Единственный слой с `Illuminate\*`
  и Eloquent-моделями.
- `src/Presentation/` — точки входа: контроллеры программного интерфейса, обработчики
  веб-обработчиков Telegram и VK, консольные команды. Тонкие: разбор запроса →
  вызов сценария → преобразование ответа.
- `app/` — минимальный каркас Laravel (поставщики служб, связывание интерфейс → реализация).

Правило проверяется автоматически (`deptrac`, шаг гейта «границы слоёв»).

## Конвенции кода (code-gauntlet)

- Функции: 4–20 строк, одна ответственность.
- Файлы: до ~250 строк; больше — разбивать по ответственности.
- Имена: уникальные, самоописательные (поиск по коду важнее сплошного чтения).
- Типы: явные везде; `mixed`/`array` без формы — только с причиной в комментарии.
- Вложенность: максимум 2 уровня, ранний возврат вместо вложенных условий.
- Внедрение зависимостей: зависимости передаются в конструктор, не создаются внутри.
- Ошибки: своё исключение с контекстом и фактическими значениями, не «invalid input».
- Форматирование: `php-cs-fixer` обязателен перед коммитом.
- Неизменяемость: объекты-значения и события — `readonly`.

## Тесты

- Запуск всего набора: `composer test` (обёртка над `phpunit`). Без ручной подготовки.
- `tests/Unit/` — `Domain` и `Application`, без фреймворка и базы.
- `tests/Feature/` — программный интерфейс через настоящий клиент HTTP, без отключения
  посредников защиты.
- `tests/Integration/` — реализации хранилищ против PostgreSQL (в конвейере — сервис-контейнер).
- `tests/Acceptance/` — сценарии Gherkin (`features/*.feature`) и их шаги на Behat.
- Каждая новая функция получает тест; каждый исправленный дефект — тест-регрессия.
- Хотя бы один сквозной тест на каждый сценарий Gherkin, с данными, вставленными
  не по возрастанию (проверка логики «следующий по порядку»).

## Базовая безопасность (обязательно, не смягчается уровнем строгости)

- Каждый обработчик записи и чтения чувствительных данных — явная проверка прав,
  не расчёт на умолчание фреймворка. Проверяется тестом: запрос без токена → 401/403.
- Пользовательский текст в разметку — только через экранирование по умолчанию.
- Загрузка файлов — список разрешённых типов и принудительное скачивание.
- «Следующий номер / остаток / счётчик» — атомарно на уровне базы: `SELECT … FOR UPDATE`
  либо `UPDATE … SET x = x - 1 WHERE x > 0`. Проверяется параллельным запуском запросов.
- Режим отладки в закоммиченном конфиге выключен; секретов в репозитории нет.
- Удаление сущности убирает связанные записи и внешние ссылки.

## Гейт перед завершением задачи

Прогнать `composer gauntlet` (или `scripts/quality_gate.sh full`) и приложить отчёт:
тесты, покрытие, цикломатическая сложность, границы слоёв, мутационное тестирование,
`semgrep`, `composer audit`. Отчёт метриками заменяет чтение изменений построчно.
